# 员工私聊设计

## 用户目标

在现有 ERP 中搜索并添加另一位员工，在两个分别登录的前端页面互发文字消息。交付包括新建一个普通员工账号、两个已验证的聊天页面，以及模块化代码。

## 方案与边界

采用 MIT 的 vue-advanced-chat 2.1.2 复用聊天界面，接入当前 FastAPI 身份认证及 PostgreSQL。vue3-beautiful-chat 偏向单窗口客服界面，联系人列表需要额外开发。完整独立 IM 服务会增加账号同步和部署工作。选用组件与本地后端的组合是实施者根据当前技术栈作出的决定。

后端聊天能力集中到 app/modules/chat，内部独立 models、schemas、service 和 router。外围只注册路由和在现有初始化器中增加建表入口。前端集中到 src/modules/chat，包含 API 适配、聊天页面和状态逻辑。登录凭据通过统一 auth storage 模块改为标签页独立存储。

## 首版行为

搜索启用员工的账号或姓名，结果只包含聊天展示需要的字段。添加联系人直接建立双方可见的一对一会话。相同双方并发添加只产生一个会话。添加自己返回错误。接收者停用后无法发送新消息。消息仅会话双方可查询，管理员同样需要是参与者。

消息为 1–4000 字符的非空文字，数据库保留发送者、会话、时间及客户端消息 ID。重试使用相同 ID，避免重复消息。历史记录分页，刷新页面可恢复。新消息每两秒同步一次，失败可重试，前端卸载时停止同步。

每个标签页独立保存登录状态，刷新仍保持当前标签页的账号。明确标识当前登录账号，可打开无 opener 的第二登录页。新增用户使用普通账号，不授予管理权限。

## 验收

在独立测试库验证联系人并发去重、消息重试、历史分页、越权、空消息及停用账号。前端构建通过。以 admin 搜索新账号、添加联系人，在两页分别发送消息并看到对方消息，刷新后保留。记录采用的直接添加联系人和两秒同步决定。
